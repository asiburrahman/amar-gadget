## Error and diagnostic foundation

The installed Next.js 16.4.3 error guide distinguishes `retry()` (refetch/re-render) from `reset()` (clear state without fetching). Existing root/marketing fallbacks only printed generic placeholders; the product fallback used reset. They now share an accessible unavailable/retry component, and a global document fallback covers root-layout failures. No original exception message/stack/provider data is rendered. Only a strict incident UUID or bounded numeric framework digest may be displayed as a support reference.

The server incident helper classifies a bounded allowlist of database/dependency codes and emits a small JSON record with operation/category/reference. It does not stringify exceptions, retain raw causes, invoke arbitrary getters or copy SQL, URLs, headers or identity/provider metadata. A sanitized ServiceUnavailableError carries the same reference as its digest; rethrowing it does not create another incident. The installed framework source preserves supplied digests; compiled-runtime correlation still requires final verification.

Public category/brand/catalog error responses now return explicit correlated no-store 503s instead of dumping raw database exceptions. Genuine missing-product results remain null/not-found, while failed slug/identity/alias queries propagate a sanitized service failure. Broader operation/catch instrumentation, partial-homepage failure handling and remaining error-state wiring are still pending.
