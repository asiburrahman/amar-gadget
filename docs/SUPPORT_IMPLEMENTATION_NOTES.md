## Required implementation

- Persist validated contact messages before reporting receipt. Support topics are order, warranty, seller and other; the public endpoint must not infer or expose order ownership from an optional reference.
- Require explicit permission to retain the message/contact details for handling the inquiry. Do not subscribe the sender to marketing, echo private text into diagnostics or advertise automatic email delivery.
- Bound decoded request size, string lengths and page sizes. Apply trusted-ingress IP and normalized-contact rate limits. Public submission never accepts actor, assignment or saved status authority.
- Use a random submission identity and deterministic normalized-content digest for safe exact retries. A conflicting reuse must fail rather than replace an existing message. Public responses expose only the receipt, not existing messages or another sender's contact data.
- Add a private administrator queue and detail view with actual counts, 20-record pages and status/topic filters. Current verified administrator/session authority is required for every operation and rechecked within status-write transactions.
- Keep original message content immutable. Status changes require an observed revision, a reason and a durable operation identity; retain an append-only actor/status history. Reopen must be explicit. An internal resolved state must not claim an email was sent.
- Remove unverified sample support details and service-time claims. Publish only operator-verified details; omit optional unpublished fields. Surface failures truthfully and preserve uncertain submission identity/content for exact retries without reporting success before persistence.
- Add/rehearse a reviewed migration in isolated local databases, update schema readiness and exercise actual compiled submission/admin paths. Verify failure, privacy, duplicate/conflicting retries, current authority and UI flows. Record production/browser/provider limitations explicitly.

## Foundation implemented

Validation tests cover normalized email, Bengali text, control/header injection, forged authority fields and exact limits. This foundation alone does not implement message delivery or close AUD-035.
