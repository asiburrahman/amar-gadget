# Reviewed development dependency patch

`deepmerge+4.3.1.dev.patch` mitigates the `mergeObject` result-prototype poisoning described in [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4). At review time the registry's latest release is 4.3.1 and the advisory lists no patched version. This is an explicit local source mitigation, not an upstream release or a changed package-version claim.

The existing target-side guard is insufficient when the input target has a null prototype, or already owns an enumerable `__proto__` data key. Copying that key into a new ordinary object through assignment invokes its inherited setter. The patch uses `Object.defineProperty` with normal writable/enumerable/configurable data descriptors at all three destination-write sites. This retains literal data (including symbols and nested values) without changing the destination's prototype. Existing merge guards, recursion, array behavior and custom merge selection remain in place. It patches the distributed CommonJS and UMD entries and corresponding source file; upstream license notices remain intact.

The regression suite reconstructs the original assignment only in an isolated test context and proves the poisoning path, then exercises the installed CommonJS/UMD implementations with source-side, target-side and nested payloads plus normal merge/descriptor behavior. A missing patch fails the tests. No vulnerable implementation is used by application code.

`npm ci`/`npm install` apply the committed patch through `patch-package --error-on-fail` before Prisma generation. Installation with `--ignore-scripts` must explicitly run that command before tests; the Docker builder does so after copying the source/patch directory. The `.dev.patch` suffix permits omission when this transitive development dependency is absent. The package is reached through Jest's trusted test configuration, not production request handlers. Production-only dependency scans and standalone output checks separately verify that boundary.

The original package name/version is retained. Consequently npm's advisory database still reports the package and affected Jest/ts-jest ancestors as low-severity entries. Reports must state those entries and this mitigation; do not claim the full npm audit is clean, downgrade the test runner merely to hide the graph, or suppress unrelated findings. Review and retire this patch when a verified upstream release is available, re-running all checks and the exploit regression before removing it.
